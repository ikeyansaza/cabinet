# visits（訪問記録）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** cabinet に `gallery | visits` モードを足し、訪問記録（年ごとのサマリー付き一覧・種類フィルタ・メモ・写真紐付け・行きたい場所）を `<parent_dir>/visits.json` で管理し、Notion のデータを移行する。

**Architecture:** データは parent_dir 直下の `visits.json`（`{visits:[], wishlist:[]}`）。写真との紐付けは `photos.json` の任意フィールド `visit` ＋ 撮影日一致の暗黙紐付け（実行時計算）。Rust は薄い読み書きコマンドのみ、集計・紐付けロジックは依存なしの純 JS モジュール（`node --test` でテスト）、UI は別 ES モジュール `visits.js`。gallery.js とは `body[data-mode]` と CustomEvent `cabinet:open-photo` だけで連携する。

**Tech Stack:** Tauri 2 / Rust（serde_json, tempfile でテスト）/ バンドラ無しの素の ES modules / `node --test`（Node 組込みテストランナー）

**Spec:** `docs/design/2026-11-03-visits-design.md`（§9 のエッジケース判断も正）

## Global Constraints

- 作業はブランチ `feat/visits` で行う（main に直接コミットしない）。コミットメッセージは日本語、末尾に `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`。
- テストを先に書いてから実装する（TDD）。複雑なロジックにはコメントを必ず付ける。
- mokomoko: フォントは `IBM Plex Mono` のみ（weight 300/400/500）、背景 `--bg #0a0a0a`、アクセント `--accent #44aaff` のみ、ボタンは透明背景＋ボーダーのみ（塗りなし）、角丸は 2px（カード）/ 3px（インプット）/ 4px（ライトボックス）。新しい色・CSS 変数を足さない。既存トークン（`--bg --panel --border --text --text-hi --accent --ok --err --dim`）のみ使う。
- `index.html` にインラインスタイル・`<script>` ブロックを足さない（外部 `<script type="module" src>` の追加は可）。
- DOM に入れる文字列は `textContent` か `esc()` のみ。`innerHTML` にユーザデータを渡さない。
- `gallery.js` にグローバル変数を足さない（IIFE 内に収める）。`visits.js` / `visits-logic.js` は ES module スコープに収め、`window` に何も生やさない。
- 写真・`photos.json`・`visits.json`・移行元データをリポジトリに含めない。`.superpowers/` は `.gitignore` に追加する。
- `visits.json` のスキーマ（spec §5.1）: `{"visits":[{id,date,place,event?,kind,note?}],"wishlist":[{id,place,kind,note?}]}`。`date` は `YYYY-MM-DD`。`photos.json` の追加フィールドは `visit`（訪問 ID、任意）。
- macOS 以外を想定しない。UI 文言は日本語可、モード名・ボタンは英小文字（`gallery` / `visits` / `[ add visit ]` のように既存の `[ select folder ]` 流儀）。

## Review Focus

1. `visits.json` が無い／壊れている／片方のキーだけ → 例外にせず空の `{visits:[],wishlist:[]}` で動く（Task 1 のテスト）。

4. 場所名・メモに `<script>` や `&` を含んでも文字列として表示される（Task 5 の手動確認）。
5. rescan（ウォッチャー経由含む）後も写真の `visit` が消えない（Task 2 のテスト）。

### Task 3: 純粋ロジックモジュール（JS）

**Files:**
- Create: `src/visits-logic.js`, `src/visits-logic.test.js`
- Modify: `package.json`（`"scripts"` に `"test": "node --test src/ scripts/"`）

**Interfaces:**
- Produces（すべて `export`、DOM・Tauri に依存しない）:
  - `isValidDate(s: string): boolean` — `YYYY-MM-DD` 形式かつ実在日。
  - `kindsOf(visits): string[]` — 重複なし、`localeCompare('ja')` 順。
  - `summarizeYear(visits): {count: number, byKind: Record<string, number>, uniquePlaces: number, repeats: number}` — `uniquePlaces` は `place` 完全一致、`repeats = count - uniquePlaces`。
  - `groupByYear(visits, kind = 'all'): Array<{year: string, summary: ReturnType<typeof summarizeYear>, visits: Visit[]}>` — 年は新しい順。各年の `visits` は `date` 降順（同日は `id` 降順）で、`kind` が `'all'` 以外ならその種類のみ。`summary` は **フィルタ前の年全体**から計算（spec §4）。フィルタ後に 0 件の年は返さない。
  - `linkPhotos(photos, visits): {byVisit: Map<string, Photo[]>, unassigned: Map<string, Photo[]>}` — ルール: ①`photo.visit` が `visits` に存在すればその訪問へ（日付が違っていても）。②それ以外（`visit` 無し・存在しない ID）は `photo.date` と同じ日の訪問が 1 件ならその訪問へ、2 件以上なら `unassigned` の `date` キーへ、0 件または `date` 無しなら無視。
  - `visitsOnDate(visits, date): Visit[]`
  - `makeVisitId(date, existingIds: string[]): string` — `${date}-${n}`（n は 1 から、未使用の最小）。
  - `makeWishId(existingIds: string[]): string` — `w${n}`（同様）。
  - 型（JSDoc）: `Visit = {id, date, place, event?, kind, note?}`、`Photo = {category, file, date?, visit?}`。

- [ ] **Step 1: 失敗するテストを書く**（`node:test` + `node:assert/strict`）。主な主張:
  - `summarizeYear`: 2025 の 4 件（動物園×2、美術館×2、うち場所が 3 種）で `count 4 / byKind {動物園:2, 美術館:2} / uniquePlaces 3 / repeats 1`。空配列で全 0。
  - `groupByYear`: 2025・2026 の混在で年が `['2026','2025']` の順、年内は日付降順、同日は id 降順。`kind='動物園'` のとき行は動物園のみだが `summary.count` は年全体の件数のまま。動物園が 0 件の年は結果に含まれない。
  - `linkPhotos`: (a) 同日 1 件 → `byVisit` に入る (b) 同日 2 件・`visit` 無し → `unassigned.get(date)` に入り `byVisit` には入らない (c) 同日 2 件でも `visit: id` 明示 → その訪問の `byVisit` (d) 存在しない ID を指す `visit` で同日 1 件 → 日付ルールで紐づく (e) `date` 無し／一致訪問なし → どこにも入らずエラーにならない (f) 明示 `visit` は日付不一致でも紐づく。
  - `isValidDate`: `'2025-10-12'` true、`'2025-2-3'`, `'2025-02-30'`, `''`, `'20251012'` false。
  - `makeVisitId('2025-10-12', ['2025-10-12-1'])` → `'2025-10-12-2'`、空なら `-1`、歯抜け `['…-2']` なら `-1`。`makeWishId(['w1','w3'])` → `'w2'`。
  - `kindsOf` が重複を除く。
