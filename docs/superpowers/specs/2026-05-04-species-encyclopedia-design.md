# 設計: 種別の図鑑情報（species encyclopedia）

- **日付**: 2026-05-04
- **対象**: moko.album
- **ステータス**: 設計合意済み

## 目的

動物写真のギャラリーに「図鑑」的な情報を付与する。同じ種の写真は同じ説明を共有し、ライトボックス上で写真と並べて見られるようにする。

## スコープ

含む:
- 種ごとに図鑑情報を持つ新しいデータファイル `species.json` の追加
- `photos.json` への `species` フィールド追加（任意）
- ライトボックス UI への図鑑ブロック追加

含まない:
- 図鑑情報のフィルタリング・検索（`tags` ベースのフィルタは既存のまま）
- `gen_photos.py` の変更（`species` は人手で書く）
- 専用の図鑑モード／別ページ
- 写真個別のキャプション（種共通の `description` のみ。個別キャプションは将来検討）

## データ構造

### `photos.json`（既存スキーマに1フィールド追加）

```json
{
  "file":    "kingfisher_01.jpg",
  "title":   "KINGFISHER",
  "tags":    ["bird"],
  "species": "kingfisher",
  "date":    "2024-05-20",
  "camera":  "α7IV",
  "lens":    "200-600mm f/5.6-6.3 G",
  "exif":    "f/6.3 · 1/2000s · ISO 3200"
}
```

- `species`（任意・文字列）: `species.json` のキーに一致する種 ID。無い写真は図鑑ブロックを描画しない。
- 既存フィールドは変更なし。`tags` と `species` は役割分離（`tags` = フィルタ、`species` = 図鑑情報リンク）。

### `species.json`（新規）

種 ID をキーにした辞書。

```json
{
  "kingfisher": {
    "name_ja": "カワセミ",
    "name_en": "Common Kingfisher",
    "habitat": "河川・湖沼の岸辺",
    "size":    "全長 17cm",
    "features": [
      "光沢のある青緑の背面と橙色の腹",
      "水面上をホバリングしてから飛び込む独特の捕食",
      "オスは下嘴が黒、メスは下嘴がオレンジ"
    ],
    "description": "「渓流の宝石」と呼ばれる青い羽の鳥。日本では北海道から九州まで広く分布..."
  }
}
```

全フィールド任意。書かれていないフィールドは UI で省略する。

| フィールド | 型 | 用途 |
|---|---|---|
| `name_ja` | string | 和名 |
| `name_en` | string | 英名 |
| `habitat` | string | 生息環境 |
| `size` | string | サイズ（自由記述。例: "全長 17cm"） |
| `features` | string[] | 識別ポイント・特徴の箇条書き（推奨 3〜7 項目） |
| `description` | string | 自由文。複数行可。語り・所感を含めてよい |

区切り文字は既存ルールの ` · `（スペース + 中点 + スペース）に従う。

## 読み込みとエラーハンドリング

`gallery.js` の起動シーケンスを変更し、`photos.json` と `species.json` を並列 fetch する。

| ケース | 挙動 |
|---|---|
| `species.json` が 200 で取得できる | 内容を内部辞書に保持 |
| `species.json` が 404 / ネットワークエラー / JSON パースエラー | `console.warn` を出して空辞書として続行（既存挙動を壊さない） |
| 写真に `species` フィールド無し | 図鑑ブロックを描画しない |
| 写真の `species` が `species.json` に存在しないキー | `console.warn` を出して図鑑ブロックを描画しない |

これにより `species.json` と `species` フィールドは完全にオプトイン。今ある2枚の写真には影響しない。

## ライトボックス UI

既存 `#lb` の DOM 構造に図鑑ブロックを追加する。

### レイアウト

- **デスクトップ（≥768px）**: 写真の右側に図鑑パネル。`flex` で 写真:パネル ≒ 60:40。パネルは縦スクロール可
- **モバイル（<768px）**: 写真の下に図鑑パネルをスタック

### 図鑑ブロックの構成（上から）

1. **ヘッダー**: `name_ja`（大きめ）/ `name_en`（小さめ・サブ）
2. **メタ行**: `habitat` · `size` を1行で（既存 `lb-exif` と同じスタイル）
3. 区切り線（`--border` 1px）
4. **features**: `<ul>` で箇条書き
5. 区切り線
6. **description**: 本文。`white-space: pre-wrap` で改行を保持

### スタイル方針

- 既存 CSS カスタムプロパティのみ使用（`--text`, `--text-hi`, `--border`, `--accent` など）
- 新しい色トークンは追加しない
- 塗り（`background`）は使わず、ボーダーと余白で構造を見せる
- フォントは `IBM Plex Mono`、weight は既存範囲（300/400/500）

### 表示制御

`species` が無い写真／`species.json` に該当キーが無い写真では、図鑑ブロックを **DOM ごと描画しない**。これによりライトボックスの幅・高さは従来どおりとなる。

## XSS 対策

`species.json` の値を DOM に挿入する際は **`textContent`** を使う（`esc()` 不要）。`textContent` は値を HTML として解釈しないため、`<script>` などのタグを含む文字列もそのままテキストとして扱われ XSS を防げる。`features` の各 `<li>` も `textContent` で書き込む。

`<ul>` の中身を再描画前にクリアする目的での `innerHTML = ''` は安全（外部由来の文字列を含まない代入）。

## 検証（自動テストなし、手動確認）

このプロジェクトには自動テストが無いため、以下を手動で確認する：

1. **既存写真の互換性**: 既存2枚（`species` 無し）が従来どおり表示され、ライトボックスにも変化が無いこと
2. **正常系**: サンプル `species.json` に1種だけ定義 → 該当する写真をクリック → ライトボックスに図鑑ブロックが正しく表示されること
3. **species.json 欠落**: `species.json` を一時的にリネーム → ギャラリーは動作し続け、`console.warn` のみ出ること
4. **不整合キー**: 写真の `species` を `species.json` に無い値にする → `console.warn` のみ、ブロック非描画
5. **レスポンシブ**: 768px 境界で右パネル ↔ 下スタックの切り替えが起きること
6. **XSS**: `description` に `<script>` を含めて挿入されないこと

## 影響を受けるファイル

| ファイル | 変更 |
|---|---|
| `photos.json` | 既存エントリは変更不要。新規エントリで `species` を任意で付与 |
| `species.json` | 新規作成 |
| `gallery.js` | `species.json` の並列読み込み、ライトボックスへの図鑑ブロック追加、エラーハンドリング |
| `index.html` | `#lb` 配下に図鑑ブロック用のコンテナ要素を追加 |
| `style.css` | 図鑑ブロックのレイアウト・タイポグラフィ。既存トークンのみ使用 |
| `CLAUDE.md` | `species.json` のスキーマ・`photos.json` の `species` フィールドを追記 |

## やらないこと（YAGNI）

- 種ごとの代表写真選定ロジック
- 種別の写真件数表示
- 図鑑モードへの切り替え UI
- `tags` から `species` への自動変換
- `species.json` のバリデータ（手書き運用なので使う側で検証する）
